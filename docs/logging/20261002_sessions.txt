What is it?
A method of saving data about clients that connect to a server.


What is a session?
A session is defined as when a client joins and lasts until the client quits.
It can span many levels or it might be only a few seconds long.
It only has one player associated with it. (Even though other players could be playing simultaneously)

Player info collected:
- player number (assigned by server)
- player color (requested by player, but can be overwritten by server to prevent duplicates)
- player name (set by the player) 
- ip address and port (provided by network interface)
- host name (computer name provided by network interface)

The information is stored on the server in a database table.

This database table is accessed with the following functions in the file: 'mwNetgameServerSession.cpp'

void mwNetgame::session_open(const char* address, const char* hostname, int p, int endreason)
void mwNetgame::session_update(int p, char * m_endreason)
void mwNetgame::session_update_at_level_done();
void mwNetgame::session_close(int p, int er)
void mwNetgame::session_check_active()
void mwNetgame::session_check_active_in_db()

Starting a session
---------------------------
When the server replies to a client's join request, it calls this function to start a session:
void session_open(const char* address, const char* hostname, int p, int endreason)
The id of the created row is called session_id and is stored in the player's struct 'mPlayer.loc[p].session_id'


Updating a session
------------------
When the session ends or when a level is completed the session is updated with this function:
void mwNetgame::session_update(int p, char * m_endreason)
It adds all the player stat tallies, bandwidth tallies, updates the end time and duration from current time...
If passed nullptr for endreason, session is still open, otherwise it will be closed.


Closing a session
-----------------
Closing a session id done with:
void mwNetgame::session_close(int p, int er)
This simply sets an endreason, then calls 'session_update()'


Updating a session at level done
--------------------------------
void mwNetgame::session_update_at_level_done()
tallies:
mPlayer.syn[p].stat_next_levels 
mPlayer.syn[p].stat_exits
then calls 'session_update()'


Checking players with active sessions
-------------------------------------
void mwNetgame::session_check_active()
Called every frame from server_control()
If any player has an open session, but the player is not active anymore, close the session 
if ((mPlayer.loc[p].session_id) && (!mPlayer.syn[p].active)) session_close(p, 6); // session still active, but player is not active anymore


Checking database active sessions
---------------------------------
void mwNetgame::session_check_active_in_db()
Called once per second in mLoop
Find all open sessions in database and checks that the session id matches an active player
If an active player is not found the session is closed with an endreason 'unknown'

Closing all sessions when the server exits
------------------------------------------
void mwNetgame::session_flush_active_at_server_exit()
If any players have open sessions, they are closed with endreason 'server quit'

How to enable or disable
------------------------
All of the functions have this guard at the beginning:
if (!mLog.log_types[LOG_NET_SESSION].action) return;

set_log_type_action(LOG_NET_session, 0);
set_log_type_action(LOG_NET_session, LOG_ACTION_LOG);



How to recreate the database tables
-----------------------------------
The sessions database file is stored at 'data/sessions.db'
If you delete it, it will be recreated.

mGameMoves and demo files



When a new level is loaded: 
---------------------------
HEADER values in mwGameMoves are set 
The new muid is linked with any open sessions (only on server)
void mwGameMoves::new_level()
{
   initialize();
   HEADER_create_timestamp = mMiscFnx.timestamp_UTC_ISO8601();
   HEADER_muid = mMiscFnx.generate_muid();
   HEADER_level = mLevel.play_level;
   status = 1;
   if (mNetgame.ima_server) create_gm_session_links();
}



Adding gm to db
---------------
When the level is completed and gm is saved:
save_gm() calls 'add_gm_to_db(const char *fname)' (only on server)
This adds an entry to the 'gm' table with muid, filename...etc
Then adds links to any open sessions


When a new session is started:
------------------------------
The new session_id is linked with the current HEADER_muid 
mGameMoves.create_gm_session_link(mPlayer.loc[p].session_id);
